# Home page implementation plan

Spec: `REFERENCE_AUDIT.md` §4 (home scenes), `ARCHITECTURE_PLAN.md`, `IMPLEMENTATION_PLAN.md`. Reference screenshots (read them with the Read tool, they are the visual target): `recon/screenshots/vp-d-hero.png`, `vp-d-home-900|1800|3200|5000|6200|7400|8600|9800|10900.png` (desktop 1440), `vp-m-home-1500|4200|7800|10500.png` and `vp-m-hero.png` (mobile 390), `d-home.png` / `m-home.png` (full page).

## Global Constraints
- Next 16 App Router, React 19, TypeScript strict, Tailwind v4. Tokens live in `src/app/globals.css` (`@theme`): colours `toffee toffee-deep toffee-ink honey honey-soft cocoa cocoa-soft milk sky sky-deep blush wa`, fonts `font-display` (Fraunces, headings) / `font-sans` / `font-hand` (class `.hand`), eases `--ease-pounce` `--ease-silk` `--ease-snap`. Use these, never raw hex that already has a token. Existing helpers: `.wrap`, `.btn`, `.btn-primary|ghost|wa`, `.card`, `.hand`; `src/components/Img.tsx` (use for all photos); `src/data/index.ts` (`puppies`, `families`, `faqs`, `SITE`, `puppyLabel`, `mediaUrl`).
- NO new dependencies. No `motion`/`lenis` (native CSS sticky + one small scroll listener or IntersectionObserver only). No backend.
- Page background journey: milk (hero) -> honey gradient (chat) -> terracotta/toffee dusk -> cocoa night. Gutter `var(--gutter)`. Header is sticky 76px/64px so scenes sit under it.
- Header inline nav appears at >=1024px; mobile bottom bar at <768px. Scenes must work at 390, 768 and 1440 widths with no horizontal page scroll.
- Respect `prefers-reduced-motion` (global CSS already shortens animations; scroll-linked scenes must still lay out sensibly with no transform animation).
- Home scenes are server components unless they need state/effects; client components get `"use client"` and live in their own file.
- Illustration art: do NOT hand-draw complex SVG. A single reusable `Mascot` (simple inline-SVG poodle face/body with a `pose` prop of at most 3 variants) is enough; simple CSS/SVG shapes for awning, skyline, sun, lamp, plane. Prioritise layout, colour, typography and photos matching the screenshots.
- Verification for every task: `npx tsc --noEmit` clean and `npx next build` succeeds. Commit on branch `feat/home` with message ending `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Touch only the files the task lists. Never run `git add -A` on `recon/screenshots`.

## Task 2: Meet the pups (sticky horizontal doors)
Files: replace `src/components/home/Meet.tsx` (client component).
Behaviour (REFERENCE_AUDIT §4.2, `vp-d-home-1800.png`): outer section is tall (about `15 doors * ~270px` so total scroll length gives ~-1.25px of horizontal travel per scrolled px; desktop outer height about 4100px); inside, a `position:sticky; top:0` stage 100vh (min 560, max 900px), `overflow:hidden`, containing the H2 "Meet the pups" (91px at 1440), a link button "See all available puppies" -> `/puppies`, and a horizontal track of 15 doors (one per `puppies` item, card width ~280px at 1440, gap ~48px) whose `translateX` is driven by scroll progress through the outer section (one rAF-throttled passive scroll listener; compute progress = clamp((scrollY - sectionTop) / (sectionHeight - stageHeight)); translateX = -progress * (trackWidth - viewportWidth)). A door is "open" (shows the puppy cover photo in an arch frame, "Available" tag, name, "breed · gender · age", "with video" label if it has a video; whole door links to `/puppies/{slug}`) when its centre is within the viewport, otherwise "closed": brown arch with a paw knob. A wooden floor strip and `Mascot` stand at the bottom of the stage. Under 768px: same mechanism with doors ~70vw wide (the reference shows a 2-column grid on mobile: use a plain 2-column grid, non-sticky, all doors open, on <768px instead of the track).
Done when: scrolling the home page moves the track horizontally while the stage stays pinned, doors open as they enter, then the stage releases and the next scene follows with no gap or overlap; build passes.

## Task 5: Cursor paw trail
Files: create `src/components/PawTrail.tsx` (client); edit `src/app/layout.tsx` to render `<PawTrail />` once before `</body>`.
Spec (observed from the reference source): a fixed full-viewport `<canvas>` (`pointer-events:none`, z-index 70, `aria-hidden`), rendered ONLY when `matchMedia("(hover:hover) and (pointer:fine)").matches` and not `prefers-reduced-motion: reduce`. On pointer move, stamp a paw (one pad path plus four toe ellipses via `Path2D`, scale about .27 times `min(devicePixelRatio,2)`) at positions spaced about 36px apart along the pointer path, rotated to the direction of travel and alternating left/right offset. Each print lives 1000ms: fully opaque for the first 600ms then fades to 0, drawn with `globalAlpha` .42 in toffee-ink. rAF loop runs only while prints exist. Resize handler keeps the canvas sized to the viewport with DPR scaling. No dependencies, under about 90 lines.
Done when: moving the mouse on desktop leaves fading paw prints, nothing renders on touch/reduced motion, build passes.
